## How the run was done

- The same way as on 18 Nov: every step was done in a Chromium session driven by the developer's own small Playwright scripts (the scripts of 18 Nov, copied and adapted to the new UI, plus new ones for the new rows; not the test suite, no traces, no HTML report). After each step a screenshot was taken and looked at; what was seen is written in Actual Result. Several script sessions ran at the same time, so the whole run took 15 minutes.
- Signed-in cases used a private copy of the session saved by the automated run of 10:33 (the file in the repo was only read). The cases about the login itself (LG-009, LG-013, LG-025) logged in through the login form (6 logins in total). The login was read from `.env.local` inside the scripts; it is not in any file, log or screenshot (screenshots of the form show only dummy values or empty fields).
- "API fails / offline" preconditions were made by blocking the one request in the browser (the same as DevTools request blocking): the login call (LG-026), the details call (PD-011), the reorder call (CT-017), the category save calls (CT-018), the product delete call (PL-015), the upload route (PF-009). Nothing reached the API for a blocked request. LG-027 answered one category list call with an unknown message key.
- Keyboard cases used real key presses (Tab, Shift+Tab, Space, Enter, Alt+↓, Ctrl+V) and read `document.activeElement` after each one. Colours, widths and heights in Actual Result are the computed styles of the page (read like in DevTools), checked against the screenshot.
- Data: only records named `HW3-Neeraj-manual-…` were created, changed, reordered and deleted, all through the UI: 1 product (id 20073, PF-023 → PD-002 / PL-025 / PL-026 / PD-013 → deleted in PL-015) and 1 subcategory with 2 minor categories under main category [67] (ids 624, 666, 667; CT-017 / CT-018 → deleted). No record of another developer was changed; no other category was reordered. The image files uploaded on step 2 (PF-009, PF-010, PF-023, PF-030) stay as files in the talking-club-dev bucket (no product record), as in every upload test.
- A guard in the form scripts aborted any product save request, so the form cases PF-004 / PF-009 – PF-013 / PF-022 / PF-025 / PF-030 / PF-035 could not create a product (0 save requests were sent).
- Because the sessions ran at the same time, the own product of PF-023 is visible as the first row on the screenshots of PL-006, PL-010 and PL-024 (it existed for about a minute from 10:50 IST).
